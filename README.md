사용자 PC의 0.10.0 보고서는 **14/14건**, 수치 단위 890개·항목 연결 후보 274개를 처리했습니다. 매출 금액의 단위 정리를 확인했으나 ‘R&D투자를 통해 국내 특허 10,639건’을 투자에, ‘시설투자에 따른 유형자산 증가 9조 3,596억원’을 투자액에 연결한 오류가 있었습니다. 두 문장은 원래도 확인 필요였고 학습 입력으로 사용하지 않았습니다.

명시된 금액 항목에 사람·특허 건수 등 맞지 않는 단위를 연결하지 않습니다. 항목과 수치 사이의 유형/무형/유동자산·금융상품·특허·인원 등의 다른 대상 표현은 항목 연결을 보류하고 정확한 표현 위치를 기록합니다. 단위를 읽은 것과 항목을 연결한 것은 다른 상태이며, 화면에 보류 이유를 따로 표시합니다. ‘바. 수주상황’ 같은 제목만 있는 문장도 후보에서 제외합니다. 이 제한된 규칙이 모든 수치의 뜻을 이해하거나 전체 오류를 해결한 것은 아닙니다.

‘파트너비가 매출 증가의 영향 등으로 10.8% 상승’처럼 배경 설명에 나온 매출을 그 비율에 연결하는 경우도 보류합니다. 해당 배경 표현의 정확한 위치를 보관하며 원인이나 비율의 대상을 추정하지 않습니다.

**새 폴더의 FACTS.cmd만 다시 실행**하세요. 기존 BUSINESS 자료를 읽고 별도 결과를 만듭니다. 기존 보고서·모델·OBSERVE 예측은 유지하고 추가 키 입력·재수집·재학습은 필요하지 않습니다. 사용자 보고서와 대비 예문에 따른 개발용 오류 수정이며 미사용 문서의 정확도 평가가 아닙니다. 원문 금액·건수와 위치·해시를 보존합니다. 정책은 `source_statement_measurements_v2`입니다.

## 0.10.0 — 사업 설명의 근거 문장과 수치 정리

새 폴더의 **FACTS.cmd만 실행**하세요. 기존 BUSINESS 결과의 기업·문서 종류·회계기간·본문 해시를 확인하고 원문 문단을 읽습니다. 추가 설치·키 입력·재수집은 필요하지 않습니다. 현재 OBSERVE 창과 고정 모델·예측 6개 등 기존 기록, 설명 추가 연구 모델은 유지합니다. 이번 후보를 모델 입력에 넣거나 재학습·모의매매·실제 주문하지 않습니다.

매출·이익, 수주, 투자, 비용, 위험요인 표현을 원문 문장과 함께 정리합니다. 이는 단어·표현 규칙으로 만든 **구조화 후보**이며 회사 설명의 사실 여부, 의미 이해, 주가 상승 원인을 검증한 결과는 아닙니다. 0.9의 글자 조각 모델에서 나아가 구체적 수치와 근거를 확인할 준비 단계입니다.

- 원문 수치의 정확한 문자 위치와 단위를 보존합니다. `333조 6,059억원`은 Decimal로 `333605900000000 KRW`로 정리하며 통화를 환산하지 않습니다. `%`와 `%p`를 구분합니다. 부호는 원문에 명시된 것만 사용하고 괄호·손실 단어만으로 음수를 추정하지 않습니다. 근사치·범위·단위 누락·지원하지 않는 숫자 형식은 보류합니다.
- 항목과 수치를 명확히 연결하지 못하거나 한 비율에 여러 항목이 걸리면 미확정으로 둡니다. 금액 수준과 변화액, 증감률과 비율을 모두 이해한 값이 아닙니다. 회사 전체·다른 회사·계열사·부문, 과거·현재 보고·전망, 문장에 적힌 기간·연결/별도 표현을 별도로 보관합니다. 보고서의 회계기간을 모든 문장 수치에 자동 대입하지 않습니다. 명시적 연도가 하나여도 외부 정답 검증을 뜻하지 않습니다.
- 총액·순액·자산화·차감, 동일 항목의 여러 금액, 조건·가정은 확인 필요로 남깁니다. 회사가 제시한 배경의 단서도 정확한 원문 위치로 보관하되 원인 입증으로 취급하지 않습니다. 알려진 회사·부문 표현과 다른 이름의 주어를 구분하는 제한된 규칙이며 모든 기업 관계를 확인하지 않았습니다.
- 접수번호 안에서 같은 항목·수치·기간·범위 조합의 반복 가능성을 표시합니다. 자동으로 합치거나 독립 근거 수로 늘리지 않습니다. 같은 숫자가 반드시 같은 뜻이라는 증명도 아니며 보고서 간 전체 중복 검증은 남아 있습니다. 표·병합셀·표 주석 단위는 해석하지 않습니다.
- 최신 회계기간·접수번호를 기존 기준일로 선택하고 접수일 다음 날부터 사용 가능한 시점을 보관합니다. 최신 원문이 실패하면 이전 원문으로 대신 채우지 않습니다. 기존 자료를 읽고 새 실행 폴더에만 저장하며 가격·모델·인증정보를 읽거나 수정하지 않습니다. 일부 원문 실패는 성공 자료를 보존하고 종료 코드 2로 알립니다.

브라우저의 **구조화 상태** 표와 매출 문장 예시 하나를 확인해주세요. `%LOCALAPPDATA%\Lyupang\facts\실행별 폴더`의 `summary.json`, `claims.jsonl`, `report.html`, `sources/`에 원문 블록 복사본과 읽기용 HTML을 저장합니다. 모든 후보는 접수번호·문단·문자 범위·해시로 추적하며 수치와 기간·주체 표현의 위치도 보관합니다. 화면은 항목별 최대 3문장·문장당 최대 8개 수치, 전체 후보는 JSONL에 보관합니다. 문서당 최대 10,000후보, 4,000자 초과 문장은 제외 이유를 셉니다.

사용자가 제공한 실제 14건 원문으로 파일 보존·출처 해시·발췌와 수치 위치를 확인합니다. 이는 개발용 동작 점검이며 미사용 문서와 사람이 확인한 정답에 따른 전체 추출 정확도 평가는 아닙니다. 확인 필요가 많아도 실행 오류와 구분합니다. 새로운 모델 성능이나 거래 수익률을 제시하는 기능이 아닙니다.

개발용: `python facts.py --root "자료 루트" --no-open`; 다른 BUSINESS 결과는 `--input`으로 지정합니다.

## 0.8.2 — OBSERVE의 Windows 권한 확인 출력 오류 보완

2026-10-29 사용자 PC의 실행 기록에서 `_readerthread`의 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb8`가 반복됐습니다. 그 뒤 세 종목에서 각각 2개씩 **새 예측 6개·결과 대기 6개·결과 확인 0개·검증 제외 0개**가 기록됐습니다. 첫 전향 예측의 저장 단계는 실행 기록상 확인됐으며 이후 실제 결과 비교는 아직 대기 중입니다. 이는 예측 오차 관찰이며 매매 성능 검증이나 모델 채택이 아닙니다.

설치된 kwcli 1.0.3의 `kiwoom.core.platform_paths`는 Windows 권한 확인용 `icacls` 출력을 `text=True`로 캡처하지만 출력 내용은 사용하지 않고 종료 코드만 확인합니다. 실행기의 `-X utf8`는 Python 기본 디코딩을 UTF-8로 정하지만 Windows 도구의 출력 코드 페이지는 바꾸지 않아 한글 바이트를 읽는 스레드에서 오류가 발생할 수 있습니다.

- 문장마다 접수번호·회계기간·공개 가능 시각·문단 해시·문자 범위·텍스트 해시를 보관합니다. 원본과 정정은 서로 다른 접수번호로 유지하고 그 정정 접수일 이후에만 가격과 연결합니다. 같은 접수일의 여러 문서와 겹치는 관찰 구간도 표시합니다.
- 가격 결과는 **접수번호×관찰 구간**마다 한 번만 만듭니다. 한 보고서의 수백 문장에 같은 결과를 복제해 독립 표본처럼 집계하지 않습니다. 접수일 당일은 제외하고 다음 날 00:00 KST 이후의 첫 관찰 일봉 시가부터 해당 수의 일봉 마지막 종가까지 비교합니다. 5·20·60은 비교 구간이며 매매 보유 기간의 선택이 아닙니다.
- 연구 배치 SHA-256, 요청 기간·종목·수정주가 기준과 가격 CSV 해시를 확인합니다. 기준일 뒤의 일봉은 사용하지 않습니다. 공시가 가격 수집 시작 전이거나 공시 전 가격 이력이 없으면 뒤늦은 첫 가격에 연결하지 않고 `outside_coverage`입니다. 이후 일봉이 부족하면 `pending`, 거래량 0·상한값 등은 `quality_issue`, 가격 출처가 없거나 손상됐으면 `source_error`로 남깁니다. 가격 실패 때도 읽을 수 있는 문장 분류는 보관합니다.
- 거래소 달력·누락·특별 개장·거래정지·과거 수정주가 시점은 검증하지 않았습니다. 시장 전체나 다른 뉴스의 영향·공시의 새로운 정보 여부를 분리하지 않아 초과수익·인과관계·통계적 유의성을 주장하지 않습니다. 비용과 체결을 반영한 전략 수익률이 아닙니다. 과거 탐색 결과를 본 뒤 수정한 모델에 같은 기간을 새 미사용 검증으로 재사용할 수 없습니다.

출력은 `%LOCALAPPDATA%\Lyupang\context`의 실행별 새 폴더에 `summary.json`, `statements.jsonl`, `release_outcomes.json`, `report.html`, `sources/`를 보관합니다. 문장과 이후 가격 결과는 별도 파일이며 접수번호로 연결합니다. 원문 블록과 분류 파일·가격 결과의 해시를 추적할 수 있습니다. 기존 모델·예측 기록·사업보고서·가격 스냅샷은 수정하지 않습니다. 모든 출처를 처리하면 코드 0, 일부 출처 확인이 필요하면 성공 자료를 보존하고 코드 2입니다. 개발용: `python contextualize.py --root "자료 루트" --no-open`; 다른 BUSINESS 폴더는 `--input`입니다.

## 0.6.2 — 현대차·NAVER 실제 원문의 추가 표기 지원

0.6.1 사용자 PC 실행에서는 삼성전자 4/4건만 읽히고 현대차 0/6·NAVER 0/4건은 남았습니다. 추가로 제공된 세 종목 원문 전체에서 공백 없는 `<기후변화>`, `<당기말>` 등의 표제, `<Connected Work>` 같은 영문 표제, `송<->수신`의 화살표와 잘못 인용된 `ENG` 영문 설명 속성을 확인했습니다.

**새 폴더의 BUSINESS.cmd만 다시 실행**하세요. 기존 본문 캐시·인증정보를 재사용하고 OBSERVE의 고정 모델·예측 기록은 바꾸지 않습니다. 원본 ZIP을 지우거나 인증키를 다시 입력할 필요는 없습니다.

실제 파일에서 확인한 표제 22종만 한정하여 글자로 읽으며, 같은 이름의 닫는 태그가 있으면 실제 요소와의 구분이 모호하므로 변환하지 않습니다. 정상적인 한글 요소·속성, CDATA·주석·처리 명령은 유지합니다. 영문 속성은 시작 태그 안의 `ENG`에 한정해 다음 속성 또는 태그 끝으로 경계를 특정할 수 있을 때 내부의 여분 따옴표를 문자로 인코딩합니다. 속성값을 버리거나 없는 따옴표·닫는 태그를 새로 만들지 않습니다. 미확인 표제나 다른 잘못된 구조는 계속 오류로 표시합니다.

`xml_parsing`의 정책은 `literal_text_characters_v2`이며 처리한 표제별 수, 영문 속성·따옴표 수, 원본·해석용 XML 해시를 기록합니다. 특수문자 수·파일 크기·노드 한도 및 기업·보고서 종류·공개 시점 검사는 유지합니다. 출처의 영어 표시 속성을 예측 변수나 재무 수치로 사용하지 않습니다.

사용자가 제공한 **삼성전자 4건·현대차 6건·NAVER 4건**에서 본문 읽기와 4개 항목 추출, 일괄 보고서 생성까지 확인했습니다. 실제 캐시로 네트워크 없이 14/14건을 처리하고 모든 발췌의 문자 범위·해시와 원본 불변도 대조했습니다. 발췌는 원문 순서의 부분 문자열이며 회사 설명의 사실성이나 주가 상승 원인을 입증하지 않습니다. 제공된 원문 파일은 저장소·배포 ZIP에 포함하지 않습니다.

## 0.6.1 — 실제 DART 본문의 특수문자 표기 지원

사용자 PC의 0.6.0 실행에서 14건 모두 XML 읽기 오류가 났습니다. 첨부된 삼성전자 사업보고서 4건으로 동일 오류를 재현했습니다. 실제 본문에 `R&D`, `S&P`의 문자 `&`와 `< TV 시장점유율 추이 >`, `<이사ㆍ감사 전체의 보수현황>` 같은 표기가 이스케이프되지 않은 채 들어 있었으며, 일반 XML 파서가 이를 거부했습니다.

본문 글자를 보존하면서 읽을 수 있게, 해석용 사본에서 확인된 문자 표기만 XML 문자 참조로 바꿉니다. 이미 유효한 문자 참조와 CDATA·주석·처리 명령, 유효한 한글 태그·속성은 변경하지 않습니다. 알 수 없는 엔티티, 잘못된 태그 짝·구조, DTD/엔티티 선언은 계속 거부합니다. 한글 꺾쇠 표기는 내부 공백이 있고 XML 속성·닫기 태그 구문이 없는 형태만 대상으로 합니다. 원본 ZIP/XML은 변경하지 않고 원본·해석용 사본 해시와 처리 수를 `xml_parsing`에 기록합니다. 미지원 형식 오류에는 본문 행·열·형식 코드를 표시합니다.

첨부된 삼성전자 실제 원문 4/4건에서 기업·사업보고서 종류 확인, 4개 항목 발췌, 전체 결과 보고서 생성, 인용문 부분 문자열·해시 대조까지 검증했습니다. 원본 파일이 유지되고 네트워크 재다운로드 없이 캐시로 처리되는 것도 확인했습니다. **현대차·NAVER의 나머지 10건은 실제 재실행 결과를 추가 확인해야 합니다.** 첨부 원문 자체는 소스 저장소나 배포 ZIP에 포함하지 않습니다.

## 0.6.0 — 사업보고서 사업·실적 설명의 출처별 수집

새 폴더의 **BUSINESS.cmd**를 실행하세요. 기존 DART 인증정보와 최신 RESEARCH의 종목·기간을 재사용하여 사업보고서 본문을 수집합니다. 가격 재수집·재학습·키 재등록은 필요하지 않습니다. 현재 켜둔 OBSERVE 실행 창과 별도로 실행할 수 있습니다. 기존 고정 모델·예측·결과 파일은 수정하지 않습니다.

브라우저에 **사업보고서 근거 모음**이 열립니다. **자료 수집 상태**의 종목별 원문 읽기 수, 사업 개요·주요 제품/서비스·실적 설명·위험요인 발췌 수와 **확인할 내용**을 확인하세요. 초기 원문 다운로드에는 시간이 걸립니다. 새 수집·파싱은 가상 응답으로 검증했으며, 실제 Windows의 DART 본문 형식·연결은 추가 확인이 필요합니다. 클라우드에 DART 키를 추가로 등록할 필요는 없습니다.

- OpenDART 공식 `document.xml` API에서 접수번호별 본문 ZIP을 받습니다. 기존 XBRL 숫자 원문과 다른 자료입니다. HTTPS 고정 주소·기존 인증키 보호 정책을 그대로 사용하고 원문 오류 응답이나 인증키가 든 URL을 기록하지 않습니다.

- 발췌에는 접수번호·접수일·사용 가능일·원문 제목 경로·XML 노드 경로·본문 블록 ID·문자 범위·해시가 있습니다. 인용문은 저장된 평문 블록의 정확한 부분 문자열입니다. **추출 본문의 해당 문단 보기**는 발췌 앞뒤의 전체 추출 문단과 표를 보여주고, **DART 공시 원문 열기**는 공식 접수번호 화면으로 연결합니다. 원격 HTML/스크립트는 실행하지 않습니다.

- **회사가 보고서에서 밝힌 설명의 발췌**입니다. 설명 자체의 진실성이나 주가 상승 원인·인과관계를 검증하거나 기업의 의미를 이해한 학습 결과는 아닙니다. 자동으로 찾지 못했다고 해당 내용이 원문에 없다는 뜻은 아닙니다. 본문을 기존 예측 입력에 넣거나, 모델을 재학습·채택·주문하지 않습니다. 이후 본문 모델을 만들 때 이미 본 평가 기간을 새 미사용 검증으로 재사용하면 안 됩니다.

ZIP은 별도 `business_documents` 캐시에 수집 시각·식별번호·SHA-256과 보관합니다. 캐시 해시가 다르면 기존 파일을 보존하고 새 복사본을 받습니다. XML 엔티티/DTD, 압축 경로·노드·크기 한도를 확인하며 ZIP을 파일시스템에 풀어 실행하지 않습니다. 파생 보고서 저장 실패 시 완료 폴더를 만들지 않습니다.

모든 원문과 4개 항목이 준비된 경우에만 완료 코드 0입니다. 일부 항목·원문 확인이 필요하면 성공한 자료를 보존하고 코드 2와 이유를 표시합니다. 개발용: `python business.py --root "자료 루트" --no-open`; 다른 연구 폴더는 `--input`으로 지정합니다.

- `%LOCALAPPDATA%\Lyupang\diagnostics`에 `diagnostics.json`, `test_predictions.csv`, `report.html`을 새 폴더로 저장합니다. 이 예측 파일은 진단에 사용한 역사적 평가 자료이며, 앞으로 실제로 예측했다는 기록이나 모의매매 원장이 아닙니다.

- 원문 모델은 유지하고, `automatic_promotion`, `fresh_unseen_evidence`, `live_trading_allowed`는 false로 둡니다. 이후에는 새 기간의 검증, 앞으로 기록할 모의매매, 비용·체결·시장 전체 편향 확인 등이 필요합니다. 이번에 모델을 더 복잡하게 바꾸거나 보유 기간을 확정하지는 않습니다.

### 과거 당시의 재무 정보 연결

- 현재값 재무 API의 비교 연도 수치를 과거에 알려졌던 값으로 대체하지 않습니다. 금융감독원의 **접수번호별 재무제표 원본파일(XBRL)** API에서 원문을 받습니다.
- 기업 식별번호·회계기간·원화 단위·재무 범위를 확인하고, 표준 IFRS의 자산·부채·매출·순이익 항목만 읽습니다. 부채/자산 비율, 순이익률과 같은 원문에 보고된 매출 전년 대비 변화를 계산합니다. 연결(CFS), 범위 표기 없는 문맥(undimensioned), 별도(OFS)를 구분하고 섞지 않습니다. 범위 표기 없는 문맥을 연결 재무제표라고 추정하지 않습니다.
- 사업보고서의 회계기간과 실제 접수일은 구분합니다. 시각 정보가 없으므로 **접수일 다음 날 이후의 관찰 사례에만** 사용합니다. 같은 회계기간의 정정은 그 정정의 접수일 이후에만 적용합니다. 가장 최신 회계기간 안에서 최신 제출본을 선택합니다.
- 최신 정정 원문을 읽지 못하거나 같은 날 여러 제출본이 있으면 이전 값으로 대신 채우지 않습니다. 기업·기간·범위가 맞지 않거나 상충하는 수치, 비표준 형식, 확인하지 못한 원문은 제외합니다. 임의로 원문 내용을 추측하지 않습니다.
- 모든 기업의 태그와 문서를 지원하는 범용 XBRL 검증기는 아닙니다. 분기·반기, 인라인 XBRL, 기업 고유 확장 태그, 여러 사업부 차원이 필요한 항목은 현재 대상에서 제외합니다. 원문을 못 읽으면 보고서와 `financial_audit.json`에 이유가 남습니다.
- `financial_documents`에 원문 ZIP과 접수번호·해시·수집 시각을 저장합니다. 인증키가 든 요청 URL이나 오류 응답을 원문으로 저장하지 않습니다.

### 첫 학습 모델과 검증

명시적인 원문 연결이 성공한 사례만 사용해 5·20·60개 일봉 이후의 비용 전 가격 변화를 각각 예측하는 **연구용 릿지 회귀** 모델을 학습합니다. 원문 재무가 없으면 가격만으로 몰래 대체해 학습하지 않습니다. 일부 재무 항목이 없는 열은 학습 구간의 중앙값으로 보정합니다. 해당 재무 수치 자체를 원문에 존재하는 값으로 저장하는 것은 아닙니다.

입력은 과거 가격 변화, 거래량 비율, 이전 공시 건수, 부채/자산 비율, 순이익률, 매출 증가율입니다. 미래 결과 열과 절대 가격 수준은 입력으로 받지 않습니다. 사업의 의미나 상승 원인의 인과관계를 자동으로 이해하는 모델은 아닙니다.

1. 모든 종목에 같은 날짜 기준을 적용해 앞 60% 날짜는 학습, 다음 20%는 검증, 마지막 20%는 최종 평가에 배정합니다.
2. 앞 구간의 미래 결과 종료일이 다음 구간 시작일 이상이면 앞 구간에서 제외합니다. 60거래일 결과가 검증·평가 기간에 걸쳐 있는 사례를 미리 학습하지 않습니다.
3. 결측값 보정·표준화·모델 선택은 학습·검증 자료로만 수행합니다. 최종 평가 자료는 이 과정에 사용하지 않습니다.
4. 각 구간 최소 100/30/30개 유효 사례가 필요합니다. 원문 연결과 표본 조건이 부족한 관찰 구간은 ‘학습 대기’로 표시합니다.
5. 최종 평가 오차와, 과거 평균 변화만 예측하는 비교 기준의 오차를 함께 표시합니다. 낮은 오차가 투자 수익을 뜻하지 않습니다. 관찰 구간은 실제 보유 기간을 확정한 것이 아닙니다.

결과에는 `features_with_financials.csv`, `future_outcomes.csv`, `financial_audit.json`, `summary.json`, `models.json`, `report.html`이 있습니다. 모델은 실행 가능한 임의 코드 형식이 아닌 JSON으로 저장하며, 연구용·실전 사용 불가 표시를 유지합니다. 새 학습 결과는 새 폴더에 저장하고 과거 모델을 덮어쓰지 않습니다.

원문별 연결을 확인해도 전체 데이터의 과거 시점 일치를 인증하지는 않습니다. 과거 수정주가 시점, 시장 전체·상장폐지 종목 편향, 거래일 달력, 겹치는 표본의 통계적 불확실성, 거래 비용·체결 가능성, 모의매매 검증은 남아 있습니다. 따라서 `point_in_time_verified`, `production_training_ready`, `live_trading_allowed`는 false입니다. 모델이 학습됐다는 이유로 실제 주문을 켜지 않습니다.

공식 원문 규격: [OpenDART 재무제표 원본파일](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019019).

### 금융감독원 OpenDART 연결

사용자는 DART 인증키가 아직 없다고 확인했습니다. [OpenDART](https://opendart.fss.or.kr/)의 **인증키 신청/관리 → 인증키 신청**에서 발급받으세요. 키움의 실전 인증키와는 별개입니다.

1. 새 버전 폴더에서 **DART_SETUP.cmd**를 실행합니다.
2. 발급받은 40자리 DART 키를 그 창에 직접 입력합니다. 입력은 표시되지 않습니다.
3. 기업개황 조회로 검증한 뒤 윈도우 보안 저장소에 저장합니다. 채팅·코드·일반 설정 파일에는 키를 넣지 않습니다. 기존 정상 키는 재입력 없이 확인하고 유지합니다. `--replace`는 검증된 새 키로 교체할 때만 사용합니다.
4. **RESEARCH.cmd**를 실행합니다. 기업 고유번호, 공시 접수일·보고서명·원문 링크, 직전 사업연도의 연간 재무제표를 수집합니다. 연간 재무제표는 연결(CFS)이 없을 때만 별도(OFS)로 조회합니다.

DART 키가 없거나 읽기 실패하면 연결 대기로 구분합니다. ‘공시 없음(0건)’으로 만들지 않습니다. 공시 목록은 정정 보고서를 포함한 전체 제출 건을 페이지별로 받고 접수번호를 구분합니다. 시각 정보가 없는 같은 날 공시는 과거 정보 계산에서 제외합니다. 재무 API의 현재 수치는 이후 정정됐을 수 있어 별도 JSON에 저장하고, **과거 예측 입력에는 넣지 않습니다**. 원문·공개 시점 검증을 끝내기 전까지 과거 정보로 인증하지 않습니다. 공시 제목이나 가격 변화만으로 상승 원인을 입증하지 않습니다.

키는 로컬 `keyring`의 `Lyupang/OpenDART` 항목에서 사용합니다. 별도로 설정된 클라우드 `DART_API_KEY`도 지원하지만, 윈도우 키 등록을 위해 클라우드에 같은 키를 중복 입력할 필요는 없습니다. 네트워크 요청은 HTTPS의 고정 OpenDART 호스트로만 보내며 인증키가 든 URL과 원문 오류를 출력하지 않습니다. 키가 실려 다른 주소로 이동하지 않도록 리디렉션을 따르지 않습니다.

새 기능은 가상 응답으로 검증합니다. 여러 종목·DART의 실제 수집과 새 윈도우 실행기는 아직 PC에서 확인해야 합니다. 기존 단일 종목 수집은 2026-10-27 사용자 PC에서 삼성전자 729거래일(2023-10-26~2026-10-26), 2페이지, CSV 저장까지 확인됐습니다.

```powershell
.\RESEARCH.cmd --codes 005930,005380,035420
.\RESEARCH.cmd --codes 005930 --prices-only
```

현재 `training_ready`, `point_in_time_verified`, `trading_enabled`는 모두 false입니다. 시장 전체·상장폐지 종목의 편향 처리, 거래일 달력 대조, 사업·뉴스 본문 분석, 원문 기반 재무 시점 검증, 모델 학습, 모의매매와 실전 주문은 남아 있습니다.

## 수집 내용과 한계

- API는 키움 `ka10081`, `/api/dostk/chart`로 고정되어 있습니다. KRX 종목코드 6자리만 받습니다.
- 연속조회 키를 따라 과거 자료를 읽습니다. 페이지는 0.6초 이상 간격으로 요청합니다. 반복 키·빈 연속조회·역행 날짜·상충하는 중복·페이지 한도 초과는 실패입니다.
- 동일한 날짜의 같은 값은 한 번만 저장합니다. 날짜는 과거순으로 정렬합니다. 거래량은 주, 가격은 원, 거래대금은 **백만원**입니다.
- 키움 가격의 부호는 방향 표시로 처리해 가격 절댓값을 저장합니다. 거래량이 0인 날과 알려진 상한값 `4294967295`인 날은 별도 표시합니다. 수치를 임의 보간하지 않습니다.
- 수정주가가 기본입니다. 기준일까지의 액면분할 등 권리 변동을 반영할 수 있으므로 `manifest.json`에 기준일과 수집 시각을 기록합니다. 이 값은 과거 당시 시장 참여자가 알았던 정보와 동일하지 않을 수 있습니다.
- `manifest.json`은 실제 시작·종료일, 행 수, 조회 종료 이유, 품질 표시, CSV SHA-256을 기록합니다. 공급자 기록이 끝나면 요청 시작일보다 실제 시작일이 늦을 수 있습니다.
- **거래소 휴장일 달력과 대조한 누락 검증은 아직 없습니다.** 상장 전, 거래정지, 휴장과 공급자 누락을 자동으로 구별하지 못합니다. 조회를 정상 종료했다는 사실을 모든 거래일의 완전성으로 해석하지 마세요.
- 재무·공시·뉴스의 공개 시점, 상장폐지 종목, 시장 전체 종목 편향은 이후 단계입니다. 현재 결과는 학습·백테스트 준비가 끝난 데이터로 표시하지 않습니다.
- 인증키, 토큰, 계좌 잔고, HTTP 헤더와 원문 오류는 결과에 저장하지 않습니다. 인증정보는 기존 SDK가 윈도우 자격 증명 저장소에서 사용합니다.
